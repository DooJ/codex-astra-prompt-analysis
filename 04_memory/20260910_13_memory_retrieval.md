# 13. 기억 조회와 근거 확인

분류: 기존 지식을 현재 업무에 불러오는 절차 · 기준: 2026-09-10 공개 판본

이 문서는 공개 자료의 해설이며, 현재 환경에 실행 지침으로 설치된 문서가 아닙니다.

## 어떤 상황을 다루는가

이전 작업에서 확인한 지식이나 사용자 선호를 현재 업무에 활용하면서, 오래된 정보를 현재 사실로 잘못 적용하지 않게 하는 부분이다.

## 기억을 읽는 기준

원문은 단순 번역·문장 다듬기·현재 시간처럼 독립적인 요청에서는 기억 조회를 생략할 수 있게 한다. 반면 프로젝트, 과거 결정, 반복 작업이나 이전 맥락이 결과에 영향을 주면 관련 기억을 찾도록 한다.

## 조회 구조

| 자료 | 역할 |
|---|---|
| memory_summary.md | 어떤 지식이 있는지 알려주는 압축 안내 |
| MEMORY.md | 검색 가능한 업무별 지식과 근거 연결 |
| skills/ | 재사용 가능한 업무 절차 |
| rollout_summaries/ 및 실행 기록 | 이전 작업의 상세 결과와 근거 |

원문 일부는 요약 파일과 원시 JSONL 실행 기록을 같은 경로 설명 안에서 혼용한다. 실제 파일 형식과 경로는 확인해야 한다.

## 처리 흐름

1. 이미 제공된 요약에서 현재 업무와 관련된 검색어를 찾는다.
2. 기억 본문에서 검색한다.
3. 연결된 자료 중 가장 관련 있는 소수의 문서만 읽는다.
4. 명령·오류 문구·세부 근거가 필요하면 실행 기록까지 확인한다.
5. 관련 내용이 없으면 조회를 끝내고 현재 작업으로 돌아간다.

## 검증과 보고

- 바뀌기 쉬우면서 확인 비용이 낮은 사실은 현재 상태로 다시 확인한다.
- 현재 파일과 환경의 직접 증거가 오래된 기억보다 우선한다.
- 검증하지 않은 기억의 내용을 현재 확인한 사실처럼 말하지 않는다.
- 사용한 기억의 출처를 연결하고, 오래됐을 가능성이 있으면 구분한다.
- 반복 오류나 이해되지 않는 동작이 생기면 관련 기억을 다시 찾아볼 수 있다.

## 예외와 경계

원문의 빠른 조회 지침에는 대략 4–6단계 검색 예산과 관련 문서 1–2개 우선 조회가 나온다. 이는 가벼운 조회를 유도하는 템플릿 설정이지 모든 작업에 적용되는 절대 한도는 아니다.

특정 기억 인용 태그는 해당 제품의 표시·추적 형식이다. 다른 시스템에 그대로 적용할 필요는 없다.

## 이해를 위한 사례

이전에 기록한 빌드 명령은 작업을 시작하는 단서가 된다. 현재 빌드 설정이 바뀌었다면 새 설정을 확인하고 기억을 그대로 실행하지 않는다. 설명용 사례다.

## 재사용 관점

기억은 현재 조사의 출발점과 지름길이다. 조회 범위를 좁히는 색인과 사실을 확인할 수 있는 근거 링크가 함께 있어야 한다.
