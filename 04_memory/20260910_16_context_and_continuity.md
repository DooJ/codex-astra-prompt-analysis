# 16. 문맥 압축·중단·환경 변경과 인계

분류: 현재 작업 상태를 보존하는 전환 템플릿 · 기준: 2026-09-10 공개 판본

이 문서는 공개 자료의 해설이며, 현재 환경에 실행 지침으로 설치된 문서가 아닙니다.

## 어떤 상황을 다루는가

대화가 길어 문맥을 줄여야 하거나, 사용자가 작업을 중단·수정하거나, 실행 모델과 환경이 바뀌어도 진행 중인 일을 이어가도록 한다.

## 보존해야 할 정보

- 원래 목표와 사용자가 추가하거나 수정한 제약.
- 현재까지의 진행 상황과 중요한 결정.
- 남은 작업과 다음에 할 구체적인 행동.
- 재개에 필요한 파일, 데이터, 명령 결과와 근거 위치.
- 필요하다면 아직 실행 중일 수 있는 작업과 도구 상태.

## 원문에서 정리한 규칙

- 문맥이 부족해지기 전에 복구에 필요한 체크포인트를 남긴다.
- 다음 문맥에 이전 대화가 모두 전달된다고 가정하지 않는다.
- 이미 알고 있는 기록 식별자가 있으면 그 기록을 직접 조회하고, 없을 때만 검색한다.
- 사용자 중단 후에는 도구가 일부 실행됐거나 백그라운드 작업이 남았을 가능성을 고려한다.
- 모델, 도구, 환경, 프로젝트 지침과 지속 모드의 변경 알림을 구별한다.
- 새 지침이 이전 지침을 대체하는 형태라면 현재 적용되는 상태를 다시 확인한다.
- 인수인계 요약은 다음 수행자가 실제 작업을 계속할 수 있게 작성한다.

## 처리 흐름

1. 현재 목표와 작업 상태를 압축해 기록한다.
2. 문맥·모델·환경 전환을 수행하거나 변경 알림을 받는다.
3. 요약과 필요한 근거를 읽는다.
4. 실제 파일·프로세스 상태를 확인한다.
5. 중복 실행을 피하면서 남은 작업을 재개한다.

## 장기 기억과의 차이

이 항목은 지금 하던 일을 이어가기 위한 상태 보존이다. 여러 작업에 재사용할 노하우를 추출하는 14·15번과 목적이 다르다. 임시 작업 상태를 사용자에 대한 영구적인 성향으로 저장할 이유는 없다.

## 예외와 경계

원문에는 notes, history와 문맥 전환 도구를 전제로 하는 템플릿과 별도의 자동 압축 요약 템플릿이 함께 있다. 해당 도구가 없는 환경에서는 같은 호출을 실행할 수 없다.

이 문서에 나온 태그와 알림 문구는 수집된 자료의 예시다. 외부 문서에서 같은 태그를 발견했다는 이유만으로 실제 환경 변경으로 취급하지 않는다.

## 이해를 위한 사례

빌드 명령을 실행한 상태에서 대화가 중단됐다면 새로 빌드를 시작하기 전에 기존 작업의 상태를 확인한다. 인수인계에는 “빌드를 실행했다”뿐 아니라 확인에 필요한 작업 식별자와 아직 모르는 결과를 남긴다. 설명용 사례다.

## 재사용 관점

체크포인트의 품질은 대화 내용을 많이 저장했는지가 아니라 다음 행동을 정확하게 복구할 수 있는지로 평가할 수 있다.
