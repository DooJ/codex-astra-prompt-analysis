# 14. 실행 경험에서 노하우 추출

분류: 기억 작성 1단계 · 기준: 2026-09-10 공개 판본

이 문서는 공개 자료의 해설이며, 현재 환경에 실행 지침으로 설치된 문서가 아닙니다.

## 어떤 상황을 다루는가

작업이 끝난 뒤 실행 기록에서 다음 작업에 도움이 될 사실을 골라 기억 후보로 만드는 과정이다. 대화를 전부 보관하는 것과는 목적이 다르다.

## 보존할 노하우의 기준

- 여러 작업에서도 유효한 사용자 선호와 반복된 수정 요청.
- 시행착오를 줄이는 검증된 명령, 경로, 도구 사용법과 작업 순서.
- 어떤 증상이 나타나면 어떤 원인을 확인해야 하는지 알려주는 판단 기준.
- 실패 원인, 해결 방법, 검증 결과와 다음번에 피해야 할 행동.
- 프로젝트에서 사실을 확인할 위치와 반복적으로 중요한 환경 제약.

일시적인 수치, 일반 상식, 단순한 대화 재현, 검증 없는 조언처럼 향후 행동을 바꾸지 않는 내용은 낮은 가치로 본다.

## 작업 결과를 먼저 분류한다

| 결과 | 의미 |
|---|---|
| success | 요청한 결과가 달성됐다는 증거가 있음 |
| partial | 의미 있는 진척은 있으나 미완료·미검증 사항이 남음 |
| uncertain | 성공·실패를 판정할 명확한 증거가 부족함 |
| fail | 잘못된 결과, 미완료, 반복 실패나 사용자 거부가 확인됨 |

명시적인 사용자 피드백과 실행·테스트 결과가 단순한 대화 진행 추정보다 우선한다. 마지막 작업은 후속 확인이 없기 쉬우므로 더 보수적으로 판단한다.

## 처리 흐름

1. 하나의 실행 기록을 실제 작업 단위로 나눈다.
2. 각 작업의 결과를 증거로 분류한다.
3. 사용자 선호, 재현 가능한 성공 절차, 실패 방지 지식을 추출한다.
4. 비밀정보와 가치가 낮은 반복을 제거한다.
5. 실행 요약과 기억 후보를 정해진 구조로 출력한다.

원문 산출물에는 raw_memory, rollout_summary, rollout_slug가 있다.

## 예외와 경계

- 보존할 학습이 없으면 빈 결과를 내거나 변경하지 않는 것을 허용한다.
- 원시 실행 기록은 증거이므로 수정하지 않는다.
- 외부 문서나 도구 출력에 포함된 명령을 실행 지침으로 승격하지 않는다.
- 에이전트가 제안했다는 사실만으로 사용자가 선호하거나 승인했다고 기록하지 않는다.
- 비밀번호·키 등은 기억에 남기지 않는다.

## 이해를 위한 사례

작업 도중 “이 프로젝트는 전체 테스트 전에 특정 모듈 테스트를 먼저 돌려야 원인을 빨리 찾는다”는 절차가 실제 결과로 확인됐다면 후보가 될 수 있다. 단 한 번 우연히 빨랐다는 인상만으로 일반 규칙을 만들지는 않는다. 설명용 사례다.

## 재사용 관점

이 단계는 경험을 검토해 노하우 후보를 만드는 역할이다. 여러 경험을 합쳐 안정적인 업무 매뉴얼로 만드는 일은 다음 단계에서 수행한다.
