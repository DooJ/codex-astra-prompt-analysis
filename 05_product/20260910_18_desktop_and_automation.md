# 18. 데스크톱 산출물·작업 관리·자동화

분류: Codex 데스크톱 기능별 지침 · 기준: 2026-09-10 공개 판본

이 문서는 공개 자료의 해설이며, 현재 환경에 실행 지침으로 설치된 문서가 아닙니다.

## 어떤 상황을 다루는가

일반 대화 외에 파일과 미디어를 표시하고, 작업을 관리하고, 반복 점검을 예약하는 데스크톱 앱의 기능을 연결한다.

## 산출물 표시와 작업공간

- 파일과 미디어는 앱이 이해할 수 있는 링크와 경로 형식으로 표시한다.
- 도구가 이미 반환한 미디어나 로컬 결과를 활용하고, 표시 제약을 우회하려는 불필요한 다운로드를 피한다.
- 문서·표·슬라이드 작업은 환경에서 제공하는 런타임과 라이브러리를 먼저 확인한다.
- 프로젝트 없는 작업에서는 임시 작업 파일과 사용자에게 전달할 산출물의 위치를 구분한다.
- 자동 생성된 폴더 이름으로 사용자의 언어나 취향을 추정하지 않는다.

## 작업과 사이드바 관리

원문은 작업 생성·조회·포크·인계·보관·이름 변경을 해당 도구로 처리하도록 한다. 새 사용자 소유 작업을 만드는 기능과 현재 요청 내부의 하위 에이전트를 구별한다.

진행 중인 다른 작업을 확인할 때는 상태와 커서를 활용하는 대기 기능으로 중복 조회와 반복 보고를 줄이도록 한다.

## 자동화와 정기 점검

- 자동화는 지원되는 관리 도구의 형식으로 생성·수정·삭제한다.
- 반복 점검에서 변화가 없거나 사용자가 할 일이 없으면 기본적으로 조용히 처리한다.
- 완료, 실패, 의미 있는 변화, 사용자 행동이 필요할 때 알린다.
- 사용자가 정기적인 상태 보고를 요구했다면 그 알림 의도를 반영한다.
- 점검 이유가 사라졌거나 더 이상 유효하지 않으면 자동화를 정리하거나 목적에 맞게 갱신한다.

## 처리 흐름

1. 파일 표시, 작업 관리, 반복 점검 중 어떤 앱 기능이 필요한지 정한다.
2. 해당 기능의 도구와 출력 규약을 확인한다.
3. 허용된 작업을 수행하고 결과나 상태를 확인한다.
4. 사용자가 확인할 파일·화면·알림을 적절히 제공한다.

## 예외와 다른 템플릿의 관계

원문의 정기 점검 응답에는 특정 XML 형식과 알림 여부 값이 나온다. 이는 스케줄러와 연결된 해당 제품의 계약이며 일반 대화의 응답 형식이 아니다.

프로젝트 없는 작업의 저장 경로도 변수로 남아 있는 부분이 있다. 모든 환경에 같은 폴더 구조를 적용할 수 없다.

## 이해를 위한 사례

매번 “아직 처리 중”이라는 알림을 보내는 대신 완료나 실패처럼 판단이 필요한 변화에 알리는 방식이다. 사용자가 매시간 현황을 원한다면 그 요청에 맞춘다. 설명용 사례다.

## 재사용 관점

사용자가 실제 결과에 접근할 경로와 알림을 받을 조건을 업무 절차에 포함하는 관점을 참고할 수 있다.
