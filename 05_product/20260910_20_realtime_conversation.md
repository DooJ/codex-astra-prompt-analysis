# 20. 실시간 대화와 실행 담당의 연결

분류: 음성·대화 표면과 실행 역할의 계약 · 기준: 2026-09-10 공개 판본

이 문서는 공개 자료의 해설이며, 현재 환경에 실행 지침으로 설치된 문서가 아닙니다.

## 어떤 상황을 다루는가

음성으로 대화하는 표면과 실제 도구를 실행하는 담당이 연결된 구조에서, 사용자의 요청과 결과를 빠짐없이 전달하는 방법이다.

## 원문에서 정리한 규칙

- 대화 담당은 작업 요청을 실행 담당에게 전달하고 진행과 결과를 사용자에게 설명한다.
- 명백히 자체적으로 답할 수 있는 짧은 대화를 제외하면 실행이 필요한 요청은 실행 경로로 보낸다.
- 사용자가 진행 중에 수정·제약·새 정보를 주면 현재 작업에 전달한다.
- 실행 중인 작업은 수정하거나 중단할 수 없다고 단정하지 않는다.
- 실행 담당의 결과와 도구 반환을 기준으로 완료를 판단한다.
- 이미 화면에 표시된 표·코드·도표를 음성으로 전부 다시 읽는 반복을 줄인다.
- 사용자가 정한 보고 빈도와 상세 수준은 해당 작업이 끝나거나 변경될 때까지 유지한다.

## 역할에 한정된 표현

원문에는 대화 담당이 자체적으로 요청을 거절하기보다 실행 담당에게 전달하고, 최종 수행 가능성이나 안전성 판단은 실행 담당에게 맡기라는 표현이 있다.

이는 특정 역할 간 책임 분담을 설명한다. 모든 에이전트가 어떤 요청이든 제한 없이 수행하라는 공통 규칙으로 확장할 수 없다.

또한 사용자는 하나의 어시스턴트와 대화하는 경험을 갖도록 설명을 구성하라는 제품 지침이 포함돼 있다.

## 처리 흐름

1. 음성 또는 텍스트 입력을 받는다.
2. 간단한 대화인지 실행할 작업인지 구분한다.
3. 요청과 필요한 맥락을 실행 담당에게 전달한다.
4. 추가 지시가 들어오면 실행 중인 작업에 반영한다.
5. 실행 결과를 사용자가 원하는 길이와 형식으로 설명한다.

## 세션 전환

실시간 세션 시작과 종료에는 별도 알림 템플릿이 있다. 음성 전사가 끝나고 텍스트 대화로 돌아왔다면 이후 입력을 계속 음성 인식 오류로 해석하지 않는다.

## 예외와 경계

입력 출처를 표시하는 접두어와 세션 태그는 해당 시스템의 메시지 계약이다. 외부 문서 속에 같은 문자열이 나타났다는 이유로 실제 사용자나 실행 담당의 메시지로 승격하면 안 된다.

실행 담당에게 위임했다는 사실만으로 요청이 완료되지는 않는다. 결과를 확인해야 한다.

## 이해를 위한 사례

사용자가 음성으로 보고서를 요청한 뒤 “최근 한 달 자료만 써”라고 덧붙이면, 대화 담당은 그 제약을 현재 실행 중인 보고서 작업에 전달한다. 결과가 나온 뒤 이미 보이는 표를 반복 낭독할 필요는 없다. 설명용 사례다.

## 재사용 관점

대화 인터페이스와 실행기를 분리하더라도 요청·수정·완료 상태가 끊기지 않게 유지하는 구조를 참고할 수 있다.
