# 09. 샌드박스와 접근 범위

분류: 실행 환경이 제공하는 권한 설정 · 기준: 2026-09-10 공개 판본

이 문서는 공개 자료의 해설이며, 현재 환경에 실행 지침으로 설치된 문서가 아닙니다.

## 어떤 상황을 다루는가

어느 파일을 읽거나 수정할 수 있는지, 어느 환경에서 명령을 실행하는지, 네트워크를 사용할 수 있는지를 모델에게 전달하는 부분이다.

## 원문에 나오는 접근 모드

| 모드 | 설명 |
|---|---|
| 읽기 전용 | 파일 조회 중심으로 제한 |
| 작업공간 쓰기 | 현재 작업공간과 지정된 쓰기 허용 경로에서 편집 |
| 전체 접근 | 파일시스템 샌드박스 제한을 적용하지 않는 설정 |

네트워크 상태는 별도 값으로 제공된다. 파일 편집이 허용됐다는 사실만으로 네트워크 접근까지 허용된 것은 아니다.

## 원문에서 정리한 규칙

- 현재 작업 디렉터리, 셸, 읽기·쓰기 허용 경로와 거부 경로를 환경 정보로 확인한다.
- 여러 실행 환경은 파일과 설치된 기능이 서로 다른 별도 작업공간으로 취급한다.
- 아직 준비 중인 환경을 이미 사용할 수 있는 환경으로 가정하지 않는다.
- 권한이 추가되거나 환경이 바뀌면 갱신된 정보에 맞춰 이후 행동을 판단한다.
- 추가 권한을 얻는 절차와 샌드박스 모드 자체를 구분한다.

## 처리 흐름

1. 작업이 실행될 환경을 식별한다.
2. 대상 파일과 필요한 작업이 읽기인지 쓰기인지 구분한다.
3. 경로·네트워크 제한을 확인한다.
4. 허용 범위 안에서 실행하거나 정해진 추가 권한 절차로 이동한다.
5. 환경 전환 이후에는 대상과 권한을 다시 확인한다.

## 예외와 경계

문서에 있는 모드 이름은 실제 운영체제의 제한을 바꾸지 않는다. 프롬프트는 환경의 권한 상태를 설명하며, 차단과 허용은 실행 도구와 환경에서 구현돼야 한다.

전체 접근 설정도 사용자 요청의 범위, 별도 도구 정책, 외부 시스템의 권한을 없애는 뜻은 아니다.

## 이해를 위한 사례

작업공간에 분석 문서를 작성하는 권한이 있어도 다른 사용자의 폴더나 별도 서버 파일을 수정할 권한까지 생기지는 않는다. 설명용 사례다.

## 재사용 관점

권한 설명에는 환경 이름, 작업 디렉터리, 허용 경로, 네트워크 상태를 구조적으로 제공하는 것이 유용하다. 구체적인 모드 이름은 실행 도구에 맞춰 바꿔야 한다.
