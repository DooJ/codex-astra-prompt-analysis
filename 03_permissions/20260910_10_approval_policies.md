# 10. 실행 승인과 추가 권한

분류: 실행 시 선택되는 승인 정책 · 기준: 2026-09-10 공개 판본

이 문서는 공개 자료의 해설이며, 현재 환경에 실행 지침으로 설치된 문서가 아닙니다.

## 어떤 상황을 다루는가

현재 권한으로 수행할 수 없는 행동이 있을 때 사용자나 승인 심사 기능을 통해 어떤 범위의 실행을 허용받는지 정한다.

## 원문에 나오는 정책

- 승인 요청을 하지 않는 모드: 제한을 넘는 실행을 무조건 허용한다는 의미가 아니다.
- 요청 시 승인 모드: 특정 실행에 대해 추가 권한이나 샌드박스 밖 실행을 요청할 수 있다.
- 신뢰된 규칙에 따른 모드: 미리 허용된 명령 규칙이 없으면 승인이 필요한 방식이다.
- 자동 심사: 요청된 실행을 정책에 따라 검토하는 별도 심사 경로다.

## 원문에서 정리한 규칙

- 필요한 행동과 승인 범위를 구체적으로 연결한다.
- 이미 저장된 명령 승인 규칙은 그 규칙에 해당하는 실행에 사용한다.
- 셸 명령에 연결 연산자나 파이프가 있으면 독립 실행 구간으로 나눠 평가한다.
- 필요한 추가 권한만 요청하는 방식과 제한 밖에서 전체 명령을 실행하는 방식을 구분한다.
- 승인 거절을 같은 효과의 우회 실행으로 무력화하지 않는다.
- 새로운 사실이나 실질적으로 안전한 대안이 있다면 그것을 확인한다.
- 해결되지 않은 차단은 어떤 행동이 어떤 이유로 막혔는지 설명한다.

## 처리 흐름

1. 실패 원인이 권한 부족인지 다른 실행 오류인지 확인한다.
2. 필요한 대상·작업·권한을 좁힌다.
3. 저장된 규칙이나 현재 승인으로 처리 가능한지 확인한다.
4. 해당 모드가 허용하는 승인 요청을 제출한다.
5. 승인 결과에 따라 실행하거나 차단된 부분을 명확히 남긴다.

## 예외와 경계

명령 앞부분을 허용하는 규칙은 이후의 모든 셸 동작을 무조건 허용하는 장치가 아니다. 하나의 문자열 안에 여러 명령이 들어갈 수 있기 때문이다.

원문에는 “더 안전한 대안”에 관한 안내가 여러 형태로 존재한다. 그 표현을 근거로 동일한 거절 행동을 이름만 바꿔 재시도하는 것은 정당화되지 않는다.

## 이해를 위한 사례

특정 디렉터리에 파일 하나를 쓰기 위해 필요한 권한과, 시스템 전체에서 임의 명령을 실행할 권한은 다르다. 승인 요청은 실제로 필요한 범위와 연결한다. 설명용 사례다.

## 재사용 관점

승인은 “예/아니오”만 저장하기보다 대상, 행동, 유효한 범위와 실행 맥락을 함께 관리해야 한다는 점을 참고할 수 있다.
