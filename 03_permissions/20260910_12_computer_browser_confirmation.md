# 12. 브라우저·컴퓨터 조작의 확인 단계

분류: 화면 조작에 특화된 정책 · 기준: 2026-09-10 공개 판본

이 문서는 공개 자료의 해설이며, 현재 환경에 실행 지침으로 설치된 문서가 아닙니다.

## 어떤 상황을 다루는가

화면에서 버튼을 누르거나 입력하는 행동이 실제로 어떤 결과를 만드는지 보고 사용자 확인 수준을 결정한다.

## 원문의 네 가지 확인 수준

| 수준 | 원문에서의 의미 | 대표 범주 |
|---|---|---|
| 사용자 인계 | 최종 행동은 사용자가 직접 수행 | 비밀번호 변경, 특정 고위험 금융 행동 등 |
| 실행 시 확인 | 사전 요청이 있어도 실제 행동 직전에 확인 | 복구 불가능 삭제, 법적 동의 등 |
| 사전 승인 허용 | 대상과 행동이 구체적으로 승인됐으면 진행 | 특정 정보 전송, 파일 업로드, 범위가 정해진 일반 구매 등 |
| 별도 확인 불필요 | 낮은 영향의 해당 행동은 추가 확인 없이 처리 | 읽기, 다운로드, 일부 일반 설정·소통 등 |

이 표는 수집 문서에 등장하는 분류를 설명한 것으로, 현재 제품이나 조직에서 실제로 허용하는 행동 목록을 인증하는 표가 아니다.

## 원문에서 정리한 규칙

- 클릭의 위험은 버튼 이름보다 현재 화면과 실제 영향을 기준으로 판단한다.
- 사용자가 직접 작성한 요청과 사용자가 가져온 외부 문서의 내용을 구분한다.
- 민감한 데이터를 폼에 입력하거나 URL에 넣는 것도 정보 전달로 본다.
- 민감한 전송의 승인은 데이터와 목적지를 구체적으로 포함해야 한다.
- 메시지는 수신 인원만으로 판단하지 않고 개인·법률·재정·평판 등에 미치는 영향을 고려한다.
- 일반 구매는 사용자가 지정한 대상·목적·지출 한도와 구독 등 중요한 조건 변화를 확인한다.
- 여러 확인이 필요하면 사용자가 이해할 수 있는 단위로 묶어 요청한다.

## 처리 흐름

1. 현재 화면과 실행될 행동을 확인한다.
2. 데이터 전달, 금전·법적 약속, 권한 변경과 복구 가능성을 확인한다.
3. 해당 확인 수준을 선택한다.
4. 필요한 승인을 받거나 사용자에게 제어를 넘긴다.
5. 실제 결과가 승인된 범위와 맞는지 확인한다.

## 예외와 원문 내부의 경계

시작 부분은 브라우저·컴퓨터 UI에 적용되며 셸이나 MCP에는 적용되지 않는다고 설명한다. 그러나 뒤쪽 목록에는 MCP 읽기와 기타 MCP 행동에 대한 항목도 포함돼 있다. 적용 경계가 본문 안에서 완전히 일관되지는 않는다.

기본 모델 지침의 메시지 발송 승인 요구와 이 정책의 일부 일상 소통 허용 표현도 범위가 다르다. 실제 재사용 시에는 적용 대상과 우선순위를 별도로 정해야 한다.

## 이해를 위한 사례

클라우드 문서의 이름을 바꾸는 행동과 같은 문서를 공개 링크로 전환하는 행동은 모두 버튼 클릭이지만 접근 권한에 미치는 영향이 다르다. 설명용 사례다.

## 재사용 관점

확인 단계를 세분화하는 설계는 참고할 수 있다. 개별 행동의 허용 목록은 사용하는 서비스와 조직 정책에 맞춰 검증해야 한다.
