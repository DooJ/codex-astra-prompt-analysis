# 05. Default와 Plan 실행 모드

분류: 상황별 대체 템플릿 · 기준: 2026-09-10 공개 판본

이 문서는 공개 자료의 해설이며, 현재 환경에 실행 지침으로 설치된 문서가 아닙니다.

## 어떤 상황을 다루는가

바로 작업을 수행할지, 구현 전에 중요한 결정을 정리할지를 선택한다. 원문은 두 모드를 서로 교체되는 실행 상태로 설명한다.

## 모드별 규칙

| 구분 | Default | Plan |
|---|---|---|
| 우선 행동 | 합리적인 가정으로 요청 실행 | 환경과 의도를 확인해 실행 가능한 계획 작성 |
| 질문 | 결과 품질에 실질적인 영향을 주는 정보 | 목표·범위·설계의 중요한 미결정 사항 |
| 파일 변경 | 현재 권한과 요청 범위에 따름 | 계획 수립을 위한 비변경 조사는 가능하나 구현 변경은 제한 |
| 종료 결과 | 실제 작업 결과 | 다른 수행자가 실행할 수 있는 계획 |

## Plan의 처리 흐름

1. 환경을 먼저 조사한다. 파일이나 설정으로 확인 가능한 내용을 사용자에게 되묻지 않는다.
2. 목표, 성공 조건, 사용자, 범위, 제약을 확인한다.
3. 구현 방식, 인터페이스, 데이터 흐름, 오류 상황과 검증 방식을 구체화한다.
4. 의사결정이 충분히 정리됐는지 점검한다.
5. 가정과 테스트 계획을 포함한 계획을 출력한다.

## 모드 전환 규칙

원문은 모드 전환을 해당 실행 환경에서 제공하는 모드 지침의 변경으로 정의한다. 사용자가 “실행해”라고 말하는 것만으로 Plan 상태가 자동 해제되는 것은 아니다.

진행 체크리스트를 갱신하는 도구와 Plan 모드도 구별한다. 체크리스트를 만들었다는 사실이 실행 모드를 변경하지 않는다.

## 예외와 주의점

Plan에서도 계획에 필요한 조사와 기존 상태 확인은 할 수 있다. “파일을 바꾸지 않는다”를 “아무 도구도 쓰지 않는다”로 읽으면 안 된다.

기본 목표는 중요한 결정을 정리하는 것이지만, 템플릿 후반에는 계획을 짧게 유지하고 요청하지 않은 세부 정책을 과도하게 설계하지 말라는 보완 규칙도 있다.

## 이해를 위한 사례

“현재 오류를 고쳐”는 실행 중심 작업이 될 수 있다. “데이터 저장 구조를 바꾸기 전에 이행 계획을 정리하자”는 계획 중심 작업이 될 수 있다. 사례의 모드 선택은 설명용이며 실제 앱 설정에 따라 달라진다.

## 재사용 관점

“실행할 때의 규칙”과 “계획할 때의 규칙”을 분리하고, 전환 주체와 전환 조건을 명시하는 방식으로 활용할 수 있다.
