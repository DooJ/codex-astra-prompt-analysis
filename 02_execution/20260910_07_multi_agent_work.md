# 07. 에이전트 역할·위임·협업

분류: 역할별 지침과 위임 모드 · 기준: 2026-09-10 공개 판본

이 문서는 공개 자료의 해설이며, 현재 환경에 실행 지침으로 설치된 문서가 아닙니다.

## 어떤 상황을 다루는가

큰 작업을 나눠 수행하거나, 독립 검토가 필요한 경우 여러 에이전트를 함께 사용하는 방법이다.

## 원문에서 정리한 규칙

- 주 에이전트와 하위 에이전트는 각자의 역할과 담당 작업을 갖는다.
- 하위 에이전트도 필요한 경우 다시 작업을 위임할 수 있는 구조가 설명돼 있다.
- 새 작업을 맡기는 호출, 실행 중인 에이전트에 메시지를 보내는 호출, 종료 후 다시 작업시키는 호출을 구분한다.
- 위임할 때 이전 대화의 어느 범위까지 전달할지 선택한다.
- 하위 에이전트의 최종 결과는 상위 에이전트에 전달되며 사람이 볼 수도 있다.
- 메시지는 역할, 작업과 내용을 구별할 수 있는 형식으로 전달한다.
- 실패한 에이전트가 여전히 필요하다면 적절한 협업 도구로 다시 작업을 줄 수 있다.

## 위임 모드의 차이

원문에는 명시적인 요청이나 적용 지침이 있어야 위임하는 모드와, 도움이 되는 독립 작업을 적극적으로 위임하는 모드가 모두 들어 있다. 두 규칙은 대안이므로 동시에 적용할 수 없다.

별도로 제시된 용도에는 범위가 명확히 나뉜 큰 작업, 다른 관점의 검토, 독립 조사와 검증 등이 있다.

## 처리 흐름

1. 전체 목표에서 독립적으로 수행할 수 있는 범위를 찾는다.
2. 담당 에이전트와 전달할 문맥을 정한다.
3. 작업을 위임하고 필요한 수정 사항을 메시지로 전달한다.
4. 결과나 실패 상태를 수신한다.
5. 상위 작업의 요구와 대조해 결과를 통합한다.

## 예외와 경계

에이전트를 생성할 수 있다는 사실과 현재 요청에서 생성해야 한다는 판단은 다르다. 모든 하위 작업이 병렬로 실행 가능한 것도 아니다.

다른 에이전트가 완료했다고 말한 내용은 결과 수신이다. 전체 사용자 목표의 완료를 입증하려면 주 작업에서 필요한 증거를 확인해야 한다.

## 이해를 위한 사례

설정 파일 조사와 독립적인 로그 분석을 각각 맡긴 뒤, 주 에이전트가 두 결과를 연결해 원인을 판단할 수 있다. 서로 같은 파일을 수정해야 하는 작업은 충돌 가능성도 고려해야 한다. 설명용 사례다.

## 재사용 관점

역할, 작업 범위, 인수인계 문맥, 결과 형식과 통합 책임을 위임 계약으로 정리할 수 있다. 실제 동시 실행과 메시징은 별도 도구가 필요하다.
