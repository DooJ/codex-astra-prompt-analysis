# 06. 장기 작업·후속 확인·목표와 예산

분류: 지속 실행과 목표 관리 템플릿 · 기준: 2026-09-10 공개 판본

이 문서는 공개 자료의 해설이며, 현재 환경에 실행 지침으로 설치된 문서가 아닙니다.

## 어떤 상황을 다루는가

한 번의 응답으로 끝나지 않는 구현, 실행 중인 작업의 관찰, 후속 검증을 이어가는 방법이다.

## 원문에서 정리한 규칙

- 지속 모드에서는 원래 요청과 직접 연결된 후속 확인을 수행할 수 있다.
- 후속 작업을 시작하기 전에 범위, 확인할 결과, 필요한 증거와 종료 조건을 정한다.
- 결과가 아직 진행 중이라는 이유만으로 완료하지 않는다. 반대로 관련 없는 새 일을 만들어 지속하지도 않는다.
- 현재 진행 중인 작업의 확인과 고정 일정으로 반복할 자동화를 구분한다.
- 목표는 여러 턴에 걸쳐 유지한다. 현재 턴에 맞게 성공 기준을 축소하지 않는다.
- 실제 실행 중인 프로세스를 기다리는 것과, 진행 증거 없이 상태 설명만 반복하는 것을 구분한다.
- 목표 예산이 끝나면 남은 작업과 현재 결과를 정리한다. 예산 소진은 완료의 증거가 아니다.
- 목표가 수정되면 새 목표에 맞춰 남은 작업을 조정한다.

## 처리 흐름

1. 목표와 종료 조건을 정한다.
2. 현재 상태를 확인하고 다음 유효한 행동을 수행한다.
3. 외부 작업을 기다린다면 현재 살아 있는 작업 식별자나 상태를 확인한다.
4. 결과 변화에 따라 작업을 계속하거나 판단을 수정한다.
5. 요구사항별 증거를 확보했을 때 완료한다.

## 완료·차단·예산의 구분

- 완료: 원래 요구사항이 실제 상태로 충족됨을 확인한 상태.
- 차단: 필요한 사용자 입력이나 외부 변화 없이는 더 진행할 수 없는 상태.
- 예산 제한: 허용된 자원이 소진된 상태로, 작업 성공과 별개다.

원문의 목표 템플릿은 동일한 차단 조건이 연속 세 차례의 목표 턴에서 반복됐을 때 차단 상태로 바꾸도록 한다. 이는 해당 목표 관리 기능의 구체적 정책이며 모든 시스템의 보편 규칙은 아니다.

## 예외와 다른 템플릿의 관계

자율 후속 작업은 기존 권한을 넓히지 않는다. 원문에는 종료 응답 이전에 계속 작업하는 지속 모드와, 종료 이후 다시 호출됐을 때 후속 작업을 찾는 템플릿이 함께 있다. 실행 환경이 어떤 방식으로 재개시키는지 확인해야 한다.

## 이해를 위한 사례

테스트 작업을 시작했다면 실행 성공 메시지만 받고 끝내지 않고, 종료 상태와 결과를 확인한다. 관찰 시간이 만료됐다는 이유만으로 같은 작업을 중복 시작하지 않는다. 설명용 사례다.

## 재사용 관점

작업의 완료 조건, 대기할 대상, 재개 조건, 자원 제한을 별도 상태로 관리하는 설계가 핵심이다.
