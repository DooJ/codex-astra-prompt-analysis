# 08. 스킬·커넥터·플러그인 활용

분류: 외부 지식과 기능의 선택·로딩 · 기준: 2026-09-10 공개 판본

이 문서는 공개 자료의 해설이며, 현재 환경에 실행 지침으로 설치된 문서가 아닙니다.

## 어떤 상황을 다루는가

현재 업무에 필요한 절차와 도구를 찾고, 불필요한 자료를 한꺼번에 읽지 않으면서 정확한 지침을 적용하는 방법이다.

## 구성 요소

- 스킬은 특정 작업을 위한 지침 묶음이며, 참조 자료·스크립트·템플릿을 포함할 수 있다.
- 커넥터는 외부 앱에 접근하는 도구 집합으로 설명된다.
- 플러그인은 스킬, 도구 서버, 앱 등을 묶어 제공하는 패키지다.
- 스킬 목록에 나온 소개와 실제 실행 지침 본문은 구분된다.

## 원문에서 정리한 규칙

- 사용자가 특정 스킬이나 플러그인을 지목하면 관련 기능을 우선 검토한다.
- 이름의 유사성만으로 관련 없는 스킬을 적용하지 않는다.
- 선택한 스킬의 실제 위치를 해석하고 본문을 읽는다.
- 참조 파일은 해당 스킬의 위치와 접근 방식에 맞춰 읽는다.
- 필요한 자료만 점진적으로 열고 같은 내용을 불필요하게 다시 읽지 않는다.
- 커넥터 도구는 검색으로 발견한 뒤 실제 제공된 인터페이스에 맞춰 사용한다.
- 설치되지 않은 플러그인은 설치 가능한 목록과 현재 요청을 확인한 뒤 설치 요청 기능을 사용한다.
- 기능이 없거나 접근할 수 없으면 그 상태를 밝히고 가능한 대체 방법을 선택한다.

## 처리 흐름

1. 업무와 사용자가 지목한 기능을 확인한다.
2. 스킬·도구 목록에서 관련 후보를 찾는다.
3. 실제 지침과 호출 형식을 확인한다.
4. 필요한 참조와 스크립트만 사용한다.
5. 설치나 권한이 필요한 경우 해당 환경의 절차로 처리한다.

## 예외와 다른 템플릿의 관계

본문에는 스킬 적용 판단을 유연하게 설명하는 기본 지침과, 이름·설명에 일치하면 반드시 읽도록 하는 별도 목록 템플릿이 함께 있다. 둘을 보편적인 단일 발동 조건으로 합치면 안 된다.

스킬에 “질문하라”는 문구가 있더라도 현재 작업에서 이미 승인된 내용인지, 그 조건이 실제로 적용되는지 먼저 판단하도록 하는 기본 규칙도 있다.

## 이해를 위한 사례

보고서 작성 스킬을 선택했다면 그 스킬이 지정하는 형식을 읽고 사용한다. 관련 없는 디자인·보안·자동화 스킬까지 전부 호출할 필요는 없다. 설명용 사례다.

## 재사용 관점

스킬은 업무 노하우를 분리해 필요할 때 전달하는 수단이다. 좋은 스킬 목록에는 적용 상황과 실제 본문 위치가 명확해야 한다.
